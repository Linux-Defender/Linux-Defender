# Related project and UI merger review

Review snapshot: 2026-11-11. Sources: public GitHub REST API, shallow default-branch checkouts, READMEs/changelogs/security workflows, and public issue/PR discussions. This is point-in-time research, not an automatic merge or review of private branches.

## Direction

Kira wants one installable Linux security-scanning product that keeps ClamTk behavior, gains ClamUI behavior and a modern UI, and can be maintained by reviewing both projects continuously. A literal code merge is not a small patch: ClamTk is Perl/GTK3; ClamUI 0.5.1 is a Rust core + Tauri + React/TypeScript desktop app. ClamUI is MIT-licensed; ClamTk retains its GPL/Artistic licensing. MIT code can be incorporated with notices, but the combined product needs license/attribution review before distribution.

Recommended target: one installable product with one primary modern UI. Use ClamUI's Rust/Tauri frontend and host-engine architecture as the candidate base; port ClamTk capabilities and preserve its user data, quarantine records, and CLI behavior. Keep a temporary Classic compatibility path during migration, then converge to one app entry point after feature parity and tests. The UI uses the host ClamAV install and shared system FreshClam database. Do not bundle a second engine or signature database. Review, test, then port or cherry-pick upstream updates; do not auto-merge.

ClamUI already includes scan profiles, standalone and daemon scanning, scheduling, scan history/logs, quarantine, database/update controls, VirusTotal, file-manager integrations, tray support, and a wider host-security audit. ClamTk brings its GTK workflow, per-user signatures, quarantine/restore behavior, local YARA rules, consent-based VirusTotal/urlscan controls, and existing distro plugins. Compare every feature before choosing whether to port or retain it.

### Feature parity target

| Area | Keep from ClamTk | Adopt from ClamUI | Combined target |
|---|---|---|---|
| Engine and updates | ClamAV scan options, FreshClam preference explanation, shared/per-user mode | Host engine discovery, clamd status, database health view | One system ClamAV database by default; show engine/signature age and service state; optional clamd backend only when its behavior matches the selected scan options. |
| Scan workflow | Existing GTK scanning, pause/cancel, preferences | Profiles, multiple selected targets, structured results | Modern profile-based workflow plus a Classic view until parity; multi-file CLI/context-menu support; exact per-item status and warning counts. |
| History and quarantine | Restore records and the collision-safe unique quarantine names | Searchable history/logs and review flow | One recoverable quarantine store, no automatic deletion, preserve legacy restore-data migration. |
| Scheduling | Existing cron scheduler and status | User-level systemd scheduling and profiles | UI-managed schedules with documented off-machine behavior and per-distro adapters; never silently install/enable services. |
| Extra detections | Local YARA rules; explicit VirusTotal and urlscan actions | Security audit/component view | Optional, labeled local rules and external reputation; explicit sharing consent; host-security audit separated from malware verdicts. |
| Desktop integration | GTK desktop entry and distro add-ons | Tray and file-manager launchers | One package with optional Dolphin, Nautilus, Nemo, and Thunar actions; first fix `%F` multi-selection and verify each desktop version. |
| Packaging and languages | Preserve ClamTk translations and existing metadata | Flatpak/AppImage/DEB/RPM build matrix and ClamUI localization workflow | Restore ClamTk translation sources, preserve attribution, build CachyOS/Arch first, then CI across distro families. |

## Security and quality decisions

- Preserve host ClamAV/FreshClam ownership by the OS package/service. The UI should display engine version, database age, update source, and service state; OS package managers update software while FreshClam updates definitions.
- Keep detections reviewable. No bulk deletion or automatic quarantine without clear consent and recoverable restore. Preserve ClamTk's unique quarantine-name fix.
- Port a daemon backend only with adversarial path tests: long paths, CR/LF/NUL, cancellation, exclusions, exact result paths, truncated output, and threat counts.
- Keep privileged operations behind a narrowly scoped, signed/versioned helper and Polkit policy. Avoid downloading/executing helpers in-app without a separately verified trust design.
- Keep VirusTotal hash lookup/file upload separate and consent-based; keep urlscan explicit/private-first; keep YARA and Fangfrisch-style feeds opt-in and distinct from official FreshClam definitions.
- HIPS, firewall/network administration, and rootkit-removal tools are not antivirus. Security-audit results must be accurately scoped and must not imply guaranteed protection.
