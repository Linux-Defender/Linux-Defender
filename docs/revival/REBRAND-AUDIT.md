# Linux Defender identity and upstream audit

Reviewed 2026-11-12 against the local `rebrand/linux-defender-identity` worktree (that branch has since been retired; `main` is the only branch) and current public GitHub APIs.

## Product identity

Linux Defender is the user-facing product name, and Kira (Linux-Defender) is the project owner and maintainer. The app title, app ID, desktop metadata, icons, packaging identities, installer copy, website, repository guidance, and the current changelog/release notes use Linux Defender. The app ID is `io.github.linuxdefender.linuxdefender`; first launch migrates the previous ClamUI native or Flatpak settings/data directories when the destination is empty. If both source and destination contain files, startup merges the legacy files into the current tree and renames the old directory `<name>.migrated`, preserving both copies.

The application identity migration to `linux-defender` completed on 2026-11-18. The GUI/CLI command, `linux-defender-cli`, `linux-defender-scheduled-scan`, `/usr/bin/linux-defender-apply-preferences`, the `linux-defender-event` Tauri channel, the `linux-defender` keyring service, the `linux-defender.mo` gettext domain, systemd units, cron markers, debug logs, and scheduler cache paths are now canonical. Pre-rename executables, helper installation, systemd units, cron lines, keyring entries, and `~/.config/clamui`/`~/.local/share/clamui` data remain readable as compatibility aliases so upgrades do not lose saved settings, schedules, API keys, or quarantined data. The protocol-v4 staging directory `~/.cache/clamui/privileged-staging` deliberately keeps its pre-rename path because the caller and an installed helper both validate it. See the 2026-11-18 section below for the compatibility boundaries that remain by design.

The MIT license retains the original upstream copyright notice alongside the Linux Defender contributors' notice. Preserve both notices when distributing substantial portions of MIT-licensed source; the old notice is attribution, not the current product name. See the [MIT license terms](https://opensource.org/license/mit).

## 2026-11-16 code-scanning and naming pass

- Code scanning alert #1, now closed (`rust/access-invalid-pointer`, `vendor/glib-0.18.5/src/collections/ptr_slice.rs:900`) flagged `PtrSlice::truncate` writing through a slot immediately after `ptr::drop_in_place`. The method now moves the value out with `ptr::read`, writes the null terminator, and only then drops the moved value; this matches the sibling `pop`/`remove` methods and also keeps the slot consistent if a destructor panics. A `truncate` regression test was added to the vendored crate. Current results are on the [Security overview](https://github.com/Linux-Defender/Linux-Defender/security); the historical per-alert URL no longer resolves. A successful CodeQL workflow run does not close an existing alert by itself; the analysis must record the new commit and the alert state must change to `fixed`.
- Internal names that no installed contract depended on were aligned: `crates/clamui-core` → `crates/linux-defender-core` (package `linux-defender-core`, library `linux_defender_core`), `po/clamui.pot` → `po/linux-defender.pot`, the Flatpak module `clamui` → `linux-defender`, the RPM `%{clamui_version}` macro → `%{linux_defender_version}`, and the project gettext skill `clamui-gettext` → `linux-defender-gettext`. The full installed-contract rename completed on 2026-11-18; the remaining `clamui` strings are deliberate upgrade aliases documented in that section.
- The release workflow attached nonexistent `clamui_*` and `clamui-privileged-helper-*` patterns. It now matches the packages the build scripts actually produce: `linux-defender_*`, `linux-defender-privileged-helper_*`, and `linux-defender-privileged-helper-*.rpm`.
- A name-availability check on 2026-11-18 found no owned package namespace for this project. `demosthenesk/Linux-Defender` is a separate ClamAV/Qt6 AppImage project under GPL-2.0, `seanpm2001/Linux_Defender` is unrelated, Microsoft markets its commercial Linux endpoint product as Defender, and no `linux-defender` package exists in the AUR or on Flathub. This records research, not legal advice; a trademark review would be needed before treating the name as exclusive.

## 2026-11-18 identity migration completion

- Canonical user-facing and system-visible names are now `linux-defender`: the GUI binary, `linux-defender-cli`, `linux-defender-scheduled-scan`, `/usr/bin/linux-defender-apply-preferences`, `linux-defender-event`, the `linux-defender` keyring service, `linux-defender.mo`, `linux-defender-scheduled-scan.service`/`.timer`, `linux-defender.log`, and the scheduler cache under `~/.cache/linux-defender/`.
- The config-staging directory stays at `~/.cache/clamui/privileged-staging` because it is part of the protocol-v4 wire contract: an older trusted helper validates staged sources against that exact path, and an older caller validates the new helper's staging the same way. Renaming it would break protected-configuration upgrades in both directions.
- Upgrade compatibility is retained deliberately. The privileged-helper trust check accepts `/usr/bin/clamui-apply-preferences` under the same root-owned and immutable-module rules. The scheduler recognizes and removes legacy units, recognizes `--command=clamui-scheduled-scan` and legacy cron commands before writing the new schedule, and still launches the old binary when the new one is absent. The keyring reads the legacy `clamui` service once and migrates the secret. Nautilus and Flatpak integration scripts prefer `linux-defender` and fall back to `clamui`. Uninstall removes both name sets.
- The data-directory migration keeps reading `~/.config/clamui` and `~/.local/share/clamui` when the canonical directories are empty, and merges safely when both contain files.
- The policy action ID `io.github.linux_defender.linuxdefender.apply-preferences` and the application ID `io.github.linuxdefender.linuxdefender` remain unchanged because existing desktop, Flatpak, and polkit installations reference them.
- Preferences now exposes urlscan.io API key management next to VirusTotal, using the existing keyring-backed `urlscan.key_status`/`urlscan.key_save`/`urlscan.key_delete` operations.

## Latest ClamUI update

The upstream [ClamUI v0.6.0 release](https://github.com/linx-systems/clamui/releases/tag/v0.6.0) was published 2026-11-11. Default branch head checked: `fd2481dcf95c889cf623017433cc2ff17fbe427e` (2026-11-11 22:00 UTC).

- `30a72f0` changes FreshClam's update timeout to an inactivity timeout. The equivalent configurable behavior and tests are already in Linux Defender.
- `fd2481d` removes URLhaus from the recommended feed setup. Linux Defender removes URLhaus from its suggestion and provider UI; users can still add their own custom URLs. The provider's current API documentation says authentication is required: [URLhaus API](https://urlhaus.abuse.ch/api/). Its former `urlhaus.ndb` download returns HTTP 410 Gone, so restoring it would make freshclam skip later custom sources. Linux Defender later restored URLhaus as a built-in provider: abuse.ch now requires a free abuse.ch Auth-Key on the ClamAV export endpoint (`https://urlhaus-api.abuse.ch/v2/files/exports/<auth-key>/urlhaus_clamav.ndb`, verified reachable with a fake-key probe returning HTTP 401), Linux Defender ships a product-default key, and the feed is added to the freshclam draft automatically. Preferences shows URLhaus as a provider row with no key entry or Delete control. The `Suggested` button still fills only RFXN (`rfxn.hdb`, `rfxn.ndb`) and the three InterServer files; URLhaus is added automatically.
- The suggested list now fills the draft with RFXN (`rfxn.hdb` and `rfxn.ndb`) plus the three InterServer files. All five URLs were verified over HTTPS on 2026-11-20. `Suggested` still only populates the draft; saving and applying remain explicit user actions.
- At the original review the two open ClamUI PRs were website dependency changes: [#298](https://github.com/linx-systems/clamui/pull/298) (eight grouped updates), and [#299](https://github.com/linx-systems/clamui/pull/299) (TypeScript 7.0.2). At the 2026-11-25 recheck #298 is closed and #299 is still open with five other open dependency-bump PRs; #299 remains deferred because Astro's current check rejected that compiler version in the reviewed snapshot. See the current recheck table in `RELATED-PROJECT-REVIEW.md`.
- Do not merge the ClamUI branch wholesale: it is a divergent upstream branch and would remove Linux Defender work, including URL reputation and other local integrations. Compare individual commits and port only reviewed behavior.
