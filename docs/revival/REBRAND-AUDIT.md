# Linux Defender identity and upstream audit

Reviewed 2026-11-12 against the local `rebrand/linux-defender-identity` worktree and current public GitHub APIs.

## Product identity

Linux Defender is the user-facing product name, and Kira (SAFETY-CHAT) is the project owner and maintainer. The app title, app ID, desktop metadata, icons, packaging identities, installer copy, website, repository guidance, and the current changelog/release notes use Linux Defender. The app ID is `io.github.linuxdefender.linuxdefender`; first launch migrates the previous ClamUI native or Flatpak settings/data directories when the destination is empty. If both source and destination contain files, startup stops and leaves both copies unchanged.

The source tree still contains historical project names in several technical contracts: the desktop package/binary name that provides the compatibility `clamui` command, CLI invocations, the privileged helper and polkit path, the installed `clamui.mo` gettext catalog domain, the Tauri event channel, the keyring service, and legacy directory/desktop identifiers. Existing installed helpers, scheduled scans, saved API keys, and user data depend on these. They are not public product branding, but some still appear in developer documentation. Renaming them requires compatibility launchers/protocols and tests, plus a separate migration for helper installation, cron/systemd schedules, keyring access, translations, and logs. The internal workspace crate is now `crates/linux-defender-core` (package `linux-defender-core`, library `linux_defender_core`), the gettext template is `po/linux-defender.pot`, and the Flatpak module is `linux-defender`; no installed contract depended on those names. This pass does not claim every old identifier has been removed.

The MIT license retains the original upstream copyright notice alongside the Linux Defender contributors' notice. Preserve both notices when distributing substantial portions of MIT-licensed source; the old notice is attribution, not the current product name. See the [MIT license terms](https://opensource.org/license/mit).

## 2026-11-16 code-scanning and naming pass

- Code scanning alert [#1](https://github.com/Linux-Defender/Linux-Defender/security/code-scanning/1) (`rust/access-invalid-pointer`, `vendor/glib-0.18.5/src/collections/ptr_slice.rs:900`) flagged `PtrSlice::truncate` writing through a slot immediately after `ptr::drop_in_place`. The method now moves the value out with `ptr::read`, writes the null terminator, and only then drops the moved value; this matches the sibling `pop`/`remove` methods and also keeps the slot consistent if a destructor panics. A `truncate` regression test was added to the vendored crate. A successful CodeQL workflow run does not close an existing alert by itself; the analysis must record the new commit and the alert state must change to `fixed`.
- Internal names that no installed contract depended on were aligned: `crates/clamui-core` → `crates/linux-defender-core` (package `linux-defender-core`, library `linux_defender_core`), `po/clamui.pot` → `po/linux-defender.pot`, the Flatpak module `clamui` → `linux-defender`, the RPM `%{clamui_version}` macro → `%{linux_defender_version}`, and the project gettext skill `clamui-gettext` → `linux-defender-gettext`. The installed `clamui.mo` domain, `clamui` command, `clamui-scheduled-scan`, `clamui-apply-preferences`, `clamui-event`, keyring service, legacy data directories, and cron/desktop identifiers remain compatibility contracts.
- The release workflow attached nonexistent `clamui_*` and `clamui-privileged-helper-*` patterns. It now matches the packages the build scripts actually produce: `linux-defender_*`, `linux-defender-privileged-helper_*`, and `linux-defender-privileged-helper-*.rpm`.

## Latest ClamUI update

The upstream [ClamUI v0.6.0 release](https://github.com/linx-systems/clamui/releases/tag/v0.6.0) was published 2026-11-11. Default branch head checked: `fd2481dcf95c889cf623017433cc2ff17fbe427e` (2026-11-11 22:00 UTC).

- `30a72f0` changes FreshClam's update timeout to an inactivity timeout. The equivalent configurable behavior and tests are already in Linux Defender.
- `fd2481d` removes URLhaus from the recommended feed setup. Linux Defender removes URLhaus from its suggestion and provider UI; users can still add their own custom URLs. The provider's current API documentation says authentication is required: [URLhaus API](https://urlhaus.abuse.ch/api/).
- The two open ClamUI PRs are website dependency changes: [#298](https://github.com/linx-systems/clamui/pull/298) (eight grouped updates), and [#299](https://github.com/linx-systems/clamui/pull/299) (TypeScript 7.0.2). The latter remains deferred because Astro's current check rejected that compiler version in the reviewed snapshot.
- Do not merge the ClamUI branch wholesale: it is a divergent upstream branch and would remove Linux Defender work, including URL reputation and other local integrations. Compare individual commits and port only reviewed behavior.
